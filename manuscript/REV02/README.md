# 1권 REV02 교정본

1~3장과 설치 부록 A는 REV01을, 4~11장과 나머지 부록은 manuscript의 기존 원고를 기준으로 다시 구성했다. 원본 파일은 수정하지 않는다. 장별 DOCX 11개, 부록 A~F 6개, 권말 참고문헌 1개를 별도로 유지한다. 합본과 배포용 PDF는 만들지 않는다.

## 읽는 순서

- `volume01-chapter01.docx`: 머리말·일러두기·1권의 구성·실습 환경 준비
- `volume01-chapter02.docx`: 원본 로그와 경보의 해석
- `volume01-chapter03.docx`: Discover와 DQL 검색
- `volume01-chapter04.docx`: 수집 경로와 사용자 규칙
- `volume01-chapter05.docx`: 정상 웹 요청과 입력값 검증
- `volume01-chapter06.docx`: 경로 탐색·헤더·인증 결과
- `volume01-chapter07.docx`: 웹 파일·실행 흔적의 판단
- `volume01-chapter08.docx`: SSH 인증·계정·권한
- `volume01-chapter09.docx`: 지속성 수단과 시스템 변경
- `volume01-chapter10.docx`: 네트워크 기록과 현재 상태 조회
- `volume01-chapter11.docx`: 독립된 사례의 재구성과 대응 판단
- `volume01-appendix-a.docx`: 설치 상세·환경 점검·문제 해결
- `volume01-appendix-b.docx`: 명령·구문 찾아보기
- `volume01-appendix-c.docx`: 원상복구와 문제 해결 점검표
- `volume01-appendix-d.docx`: 용어와 필드
- `volume01-appendix-e.docx`: 사례별 조사 기록 양식
- `volume01-appendix-f.docx`: 원자료 대응표와 ATT&CK 학습 범위
- `volume01-references.docx`: 장별 출처 번호와 전체 URL

각 DOCX의 쪽 번호는 해당 파일 안에서 시작한다. 1권 전체의 연속 쪽수는 합본을 만들 때 정할 항목이므로 여기서는 장·절·명령 번호로 찾는다.

## 주요 변경

장의 도입을 조사 질문과 학습 목표로 다시 쓰고, 앞 장에서 익힌 근거와 다음 장의 확인 행동을 연결했다. 같은 조사 방법과 기록 양식을 이어 사용하되 서로 다른 실습을 하나의 실제 공격 캠페인으로 합치지 않았다.

1.3~1.5와 1.9의 상세 설치 입력은 A.12~A.15로 옮겼다. 명령 번호 C01은 유지해 기존 참조와 복사용 파일을 찾을 수 있게 했다. 1장에는 환경 구성과 준비 완료 조건, 서비스·수집기 확인, 기준 상태 보존을 남겼다.

반복된 절 번호를 소절 제목으로 나누고 쪽 단위 강제 나눔을 해제했다. 제목에 Word 스타일을 적용하고 표·그림·캡션의 관계를 조정했다. 화면 메뉴와 버튼은 고딕으로 구분한다. 본문·코드 글꼴 크기를 줄여 쪽수를 맞추지 않았다.

4~11장에 예측, 관찰의 한계, 정상 행위와 비교하는 판단 문제를 추가했다. 안내를 줄이는 대상은 장말의 조사 과제이다. 실행 위치·필수 옵션·변경 전 확인·원상복구 절차는 초보자가 따라 할 수 있도록 유지했다.

수집 확인·경보 생성·검색·해석을 구분하도록 머리말과 실습 기록을 고쳤다. 2장에는 미사용 계정 확인, 유효 SSH 서버 키 경로와 지문 확인, 기존 known_hosts 보존 조건을 보완했다. 8장도 첫 접속 승인 전에 같은 종류의 서버 키 지문을 대조하도록 고쳤다. 이 절차의 검토 범위는 저자 검토 기록에 남겼다.

질문형·비유형 제목을 대상과 기능이 드러나는 제목으로 바꿨다. 실습 주소는 kt66 192.168.0.107, 공격자 192.168.0.108, 도메인 ccc.com으로 통일했다. 표 160개의 첫 행은 연한 회색 음영과 가로·세로 가운데 정렬을 적용했다.

삽화와 캡션은 가상의 실습팀이 관제 준비 보고서의 근거를 확인하고 잘못된 판단을 수정하는 내용으로 구성했다. 7·9·10장의 삽화 세 장은 종이 문서 대신 요청 전송·콘솔 조작·복구 결과 비교 장면으로 교체하고, 중복된 삽화 한 장을 삭제했다. 인물·가구·화면 방향은 새 원본과 실제 DOCX 지면에서 확인했다.

## 예제와 재생성

입력은 `examples/rev02/`에 있다. 전체 목록은 `input-index.csv`와 `input-index.json`이며, 각 행은 실제 수록 문서·절·실행 위치·파일을 연결한다. 설치 입력 일부는 부록 A에 있지만 파일은 `chapter01` 디렉터리에서 찾는다. 공통 기록 양식은 `casebook.txt`이다.

현재 JSON이 편집 원본이며 DOCX와 함께 유지한다. 수정 뒤에는 다음 순서로 복사용 입력과 DOCX를 갱신한다.

1. `tools/sync_examples_rev02.py`
2. `tools/build_volume01_rev02.py`

이전의 revise·refine·finalize·polish·style_revision·standardize_figures 등 일괄 변환 스크립트는 편집 이력이다. 현재 원고의 개별 교정까지 재현하는 전체 빌드 절차가 아니므로 다시 실행해 원고를 덮어쓰지 않는다.

`assets/figures/rev02/casebook-path.png`는 저장된 도식 자산으로 함께 유지한다. 문장 변경 뒤에는 `audit_volume01_rev02.py`, `check_inputs_rev02.py`, `check_powershell_rev02.ps1`로 정적 검사를 수행하고 DOCX 지면을 다시 확인한다. 구문 검사는 실습 실행 검증을 대신하지 않는다.

검토 기록은 `editorial/REV02/`에 있다. 기술 이력은 기존 장별 review·validation·evidence 자료와 연결해 읽는다.

## 최종 교정 검사

18개 DOCX, 합계 566쪽의 지면을 검토했다. 번호 입력 445개의 본문·복사용 파일 일치, 그림 자산 203개의 DOCX 내장 해시, 권말 참고문헌의 전체 URL 126개를 확인했다. Bash 359개와 PowerShell 5개 입력은 실행 없이 구문 검사만 수행했다. 최종 파일 해시와 문서별 결과는 `editorial/REV02/final-qa.json`, 수정 이유와 검증 범위는 `editorial/REV02/review.md`와 `style-and-story-review.md`에 있다.

## 출판 전 남은 확인

빈 PC에서의 설치 베타 테스트, 부록 A의 VMware·Ubuntu 설치 화면 두 곳, 새로 보완한 2·8장 SSH 절차의 대화형 실행 확인은 별도 작업이다. 이번 교정에서 공격 실행·VM 변경·신규 UI 촬영을 수행한 것으로 표시하지 않는다. 기존 8~10장의 실제 시험 결과와 이번 정적 교정을 구분한다.
