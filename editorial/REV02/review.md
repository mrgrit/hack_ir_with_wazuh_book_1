# REV02 구성·문체·편집 검토

작업 기준일: 2026-11-03. 대상은 1권 전체이며 REV01, 기존 manuscript 원고와 강의 저장소는 변경하지 않는다. baseline 해시는 source-baseline.json에 있다. 검토 전에 JSON의 본문·명령·해설·캡션이 기존 DOCX의 XML 텍스트와 일치하는지 확인했으며 11개 장에서 누락이 없었다.

## 집필 기준의 적용

명저의 구성 원칙은 구체적인 조사 질문, 선행 지식의 순서, 반복 사례의 변형, 인과를 설명하는 문단, 독립적으로 풀 수 있는 문제, 다시 찾아 쓸 수 있는 참조 구조로 적용했다. 짧은 문장을 유지하는 것 자체를 목표로 삼지 않았다. 조건과 결과의 연결에 필요한 문장은 보존했다.

사용자가 제공한 다른 AI와의 논의 중 하나의 캠페인으로 엮자는 제안은 기존 AGENTS.md의 사례 구분과 충돌한다. 실제로 다른 시점·대상의 실습이므로 같은 사건을 만들지 않고 같은 조사 질문과 기록 양식으로 연속성을 만들었다. 11장의 A·B·C 경계는 유지했다.

모든 장에서 규칙을 작성하도록 강제하지 않았다. 수집하지 않은 POST 본문이나 기록하지 않은 프로세스 동작은 규칙만으로 보충할 수 없다. 4장의 사용자 규칙 작성과 나머지 장의 관찰 한계·정상 행위 대조·추가 증거 판단을 구분했다. 신규 공격이나 탐지 성능 측정을 수행하지 않았다.

분석 참고 상자는 판단 기준을 설명하는 용도로 사용한다. 저자의 은행·현장 경험을 새로 꾸며 쓰지 않았다. 규칙 번호나 탐지 성공을 독자의 예상에 맞춰 단정하지 않았다.

## 기술 검토와 실제 실행의 구분

이번 작업은 원고·예제·조판의 로컬 편집이다. 새로운 SSH 접속, 공격, VM 설정 변경, 새 UI 촬영은 수행하지 않았다. 7장과 11장의 제한을 유지했다. 8~10장의 실제 시험 결과와 정적 검토 한계는 각각 기존 chapter08-review.md, chapter09-review.md, chapter10-review.md를 따른다. 11장의 PowerShell 사본 생성 확인과 DQL 재사용은 chapter11-appendices-review.md를 따른다.

2장의 신규 사전 확인 절차와 8장의 보완한 접속 순서는 기존 8·9장의 유효 HostKey 기록과 도구 구문을 대조한 것이다. 전체 대화형 순서를 새 환경에서 수행한 것으로 표시하지 않는다. /etc/ssh의 잔여 키와 /var/lib/bastion/ssh-host-keys의 유효 키를 혼동하지 않도록 sshd -T를 먼저 읽는다. C02-01과 C08-11의 HostKeyAlgorithms=ssh-ed25519는 비교할 서버 키 종류를 맞추기 위한 지정이다.

기존 examples의 원본 관찰 데이터는 그대로 보존한다. REV02의 교육용 사본 중 주소·도메인을 통일한 파일은 변환 전 사본과 전후 해시를 original-example-values/ 및 example-value-provenance.json에 보존했다. 같은 로그를 읽는 분석 과제와 같은 VM 상태를 재현하는 일은 다르므로, 전체 SIEM 스냅샷이나 검증된 가져오기 도구를 새로 제공했다고 주장하지 않는다. 2·4장의 로그, 5·6장의 요청 기록, 11장의 증거 묶음을 재사용할 수 있다.

## 조판·검사

부크크 B5 첫 구역의 판형·여백과 테마를 상속했다. 설치된 부크크 명조 Light·고딕 Light를 사용하며 코드는 Consolas이다. 읽을 글자가 많을 때 폰트를 줄이지 않았다. 쪽별로 끊던 원고를 연속 조판하고 제목 계층·머리글·쪽 번호·표 테두리를 정리했다.

문서 스킬 render_docx.py는 LibreOffice가 없어 실패했다. 설치된 Word의 별도 COM 인스턴스로 읽기 전용 열기와 PDF 출력을 수행하고 번들 Python pypdfium2로 페이지 PNG를 만들었다. PDF·PNG는 build/REV02의 내부 QA 자료이며 배포 대상이 아니다.

구조 검사에서는 본문과 복사용 입력의 일치, 입력 번호 중복, 그림 경로와 내장 그림 SHA-256, 전체 URL 문자열, 판형, 기준 원고의 해시 보존을 확인한다. 세부 결과는 structural-audit.json과 최종 QA 기록에 남긴다. 실제 환경에서 실행한 성공 결과와 이런 정적 검사를 혼동하지 않는다.

최종 r10 출력은 18개 문서, 합계 567쪽이다. 이전 r8의 검토 결과와 해시는 final-qa-r8.json에 보존했다. r9에서는 r8과 PNG 바이트가 같은 132쪽의 검토를 이어받고 달라진 435쪽을 109개 원래 크기 검수 시트에서 확인했다. r10에서는 r9와 같은 493쪽의 검토를 이어받고 달라진 74쪽을 19개 시트에서 확인했다. 제목·본문·표·명령·그림·캡션·참고문헌의 잘림과 겹침을 확인했으며, 텍스트 좌우 판면 검사에서도 초과가 없었다. 큰 화면을 읽을 수 있게 유지하면서 앞쪽에 여백이 생긴 지면은 허용했다.

445개 번호 입력은 JSON·DOCX·복사용 파일 사이에 누락이나 불일치가 없고, 사용한 그림 자산 203개는 DOCX 내장 그림의 해시와 일치한다. 일반 표 160개의 첫 행 음영 E7E7E7, 가로·세로 가운데 정렬, 반복 머리행을 XML과 렌더에서 확인했다. Bash 입력 359개와 PowerShell 입력 5개가 파서의 구문 검사를 통과했다. 명령을 실행한 검사는 아니다. 권말 참고문헌의 전체 URL 126개는 렌더된 텍스트와 대조했다. 줄바꿈·머리글을 제외하고 PDF 추출 과정의 하이픈 대체 문자를 원래 하이픈으로 정규화했으며, 주소를 축약하거나 새 하이픈을 삽입하지 않았다.

최종 문장 검사에서 인용 번호 변환이 로그의 프로세스 번호와 배열 첨자까지 바꾼 곳을 바로잡았다. 2·4장의 sshd[7249]와 11장의 [0] 설명을 원래 의미로 복원했다. 5~11장의 예제 안내와 11장의 PowerShell 경로를 examples/rev02에 맞췄다. 최종 파일 해시, 문서별 쪽수, 재검토 지면, 원본 보존과 증거 사본 대조 결과는 final-qa.json에 기록한다.

기준 원고 27개 파일의 해시는 작업 전과 같다. 재사용한 관찰 자료 49개 중 34개는 원본 바이트와 일치한다. 나머지 15개는 고정 주소·도메인으로 변환한 교육용 사본이며, 보존한 변환 전 사본이 기존 examples 원본과 같은지 확인했다. 11장의 사례 A·B·C는 증거 매니페스트의 해시·기록 수와 일치한다. 명령을 담은 입력 매니페스트는 이번 원고에 맞춰 갱신했으므로 관찰 자료 비교에서 제외했다. 인물 삽화 20개 중 재사용한 17개는 기존 illustration-physical-review.json의 개별 검토 당시 해시와 같다. 새 삽화 3개는 원본을 한 장씩 검사하고 7장 15쪽·9장 9쪽·10장 43쪽의 DOCX 배치를 확인했다. 기존 종이 장면을 반복하는 후보와 인체·가구·화면 방향에 문제가 있는 후보는 채택하지 않았다.

## 후속 교정 항목

빈 PC의 전 과정 설치 테스트와 독자 베타 테스트는 아직 수행하지 않았다. 2·8장에서 보완한 SSH 접속 순서는 대화형 실행 확인이 남아 있다. 부록 A의 설치 화면 두 곳은 기존 지침에 따라 저자 촬영 자리로 유지했다. 새 인물 삽화 3개는 개별 원본을 검사했고, 재사용한 17개는 기존 개별 검토의 해시 일치를 확인했다. 각 장의 실행·UI 검증 이력을 업데이트할 때 해당 원고와 검토 기록을 함께 고친다. REV01이나 강의 저장소에 이번 변경을 덮어쓰지 않는다.
