# 11장과 부록 초안 집필·검토 기록

검토일은 2026-11-03, 시간대는 Asia/Seoul이다. 사용자의 “1권 남은 부분 끝까지 가자” 요청에 따라 11장과 부록을 작성했다. 이후 “합본은 안해도 된다. 챕터별로 다시 교정을 할거야”라는 지시에 따라 합본은 작업·업로드 대상에서 제외했다. 일반 원고 경로의 장별 DOCX 두 개가 산출물이며 REV01의 별도 검수를 대신하지 않는다.

## 구성과 출처

11장 제목은 **사건 재구성과 대응 판단**이다. 기존 8~10장의 실습을 종합하는 장으로, 새로운 공격 실습을 추가하지 않는다. 30개 JSON 편집 단위가 Microsoft Word에서 30쪽으로 조판된다. PowerShell 명령 5개, DQL 6개, 기존 UI 4개, 새 관계 도식 5개, 재사용 삽화 1개를 제공한다.

부록은 **실습 점검과 조사 자료**로, Word에서 27쪽이다. A는 환경·위치·수집, B는 명령·검색 참조, C는 원상복구·문제 해결, D는 용어·필드, E는 조사 양식, F는 원자료 대응표이다. 재사용 삽화 한 개를 실제 삽입했다. `examples/appendices/example-index.csv`의 451개 입력은 장별 본문 JSON에서 추출했으며 입력 위치와 복사용 파일을 대조했다.

1권의 원자료는 Module01_Wazuh_위협탐지_DQL.pptx이다.

- 문서: https://docs.google.com/presentation/d/1o0H_2DDHBp8p2HvlSnEPbx6-jdURYzew/edit
- 동일 원자료의 기존 다운로드 SHA-256: `b3550f87c2342a43e72ee5ac74c9a884de6aff38631b8c77a2364d0cf5d47099`
- 사용자가 다시 보낸 `?slide=id.p105#slide=id.p105` 링크도 같은 문서이다. p105는 선택 슬라이드 식별자이다.
- 부록 F는 Module 01의 01~30과 62, 총 31개 실습을 빠짐없이 연결한다. 11장은 그 실습의 기록을 사용하는 종합 조사이며 Module 02·03의 신규 내용을 포함하지 않는다.

NIST SP 800-61 Rev. 3의 탐지·대응·복구 관점, Wazuh Event logging, Microsoft Get-FileHash, OpenSSH의 키 인증 동작을 공식 자료와 대조했다. 본문 참고자료는 제목과 전체 URL을 함께 인쇄했다. 11장 대응 양식은 기존 실습 자료를 토대로 작성한 교육용 양식이며 NIST 문서의 원본 양식으로 표시하지 않는다.

## 세 사례의 경계와 판단

| 사례 | 대상과 자료 | 판단 범위 |

KST와 UTC, 원문 발생 시각과 Wazuh timestamp를 구분했다. 같은 주소·계정·경로가 다른 호스트나 독립된 실습에도 나타날 수 있음을 설명했다. PID 재사용, NAT, 수집 간격, 첫 osquery added, 선택하지 않은 key/options 열의 관찰 한계를 포함했다. 592개 archives 문서를 포트·패킷 수로 바꾸지 않았으며 Active Response add/delete를 실제 패킷 차단 효과와 구분했다.

`examples/chapter11/evidence/manifest.json`에 발췌 기준·원본 경로·원본 커밋·해시를 기록했다. sha256은 배포 사본, source_sha256은 지정 Git 커밋의 원본 바이트, source_checkout_sha256은 집필 PC 작업 사본의 해시이다. Windows의 Git 줄바꿈 자동 변환을 고려해 배포 증거 JSON에만 `.gitattributes`의 `-text`를 적용했다. 기존 원본의 속성이나 파일은 바꾸지 않았다. 각 발췌 이벤트는 기존 원본과 대조했고, `evidence_id`와 `source_chapter`만 저자용 식별값으로 추가했다. 원본 디스크 이미지나 전체 로그로 표시하지 않는다. 원자료의 나머지 기록과 실행 증거는 각 장의 기존 `editorial/evidence/`를 따른다.

## 실제 수행한 검사와 한계

Windows의 저장소 루트에서 C11-01~05를 한 PowerShell 세션에 순서대로 실행했다. 분석 폴더 사전 부재 확인, 네 JSON 파일 복사, SHA-256 대조, JSON 객체 변환, agent/data/full_log 표시를 확인했다. 마지막 명령은 서로 다른 객체를 연속 출력할 때 자동 표의 첫 열만 적용되는 문제를 피하도록 `Format-List *`로 속성을 각각 표시한다. 실행 결과는 `evidence/chapter11/2026-11-03/`에 보관했다. 분석 사본은 검사 후 Git에서 제외되는 build 디렉터리로 이동했다.

최초 저자용 검사기는 별도 스크립트 범위에서 실행해 `$caseA`가 다음 블록에 이어지지 않았다. 동일 범위에서 순차 실행하도록 검사기를 수정하고 다섯 명령을 다시 확인했다. 본문의 변수 유지가 필요한 실행 순서는 한 PowerShell 세션을 전제로 한다. 이 검사는 로컬 분석 사본 명령에 한정된다.

Q11-01~06은 각각 Q08-05, Q09-03, Q09-04, Q10-02, Q10-04, Q10-05와 문자 단위로 같다. 기존 장의 실제 Discover 검증 기록을 재사용하며 이번 작업에서 해당 검색을 다시 실행했다고 주장하지 않는다. 검색 기간·패턴·필터·대상 값이 달라지면 결과도 달라진다. Q11-06은 archives이고 다른 다섯 검색은 alerts이다.

새 공격, 신규 UI 촬영, SSH 접속, VM 설정 변경, 운영 방화벽 조치, 계정 정지, 디스크 이미징은 수행하지 않았다. 운영 사고의 비인가 여부나 실제 피해를 확정하지 않았다. 11장의 대응 연습은 계획과 기록 작성이다. 기존 7장의 공격 실행·신규 촬영 금지 조건도 유지했다.

## 조판과 검토

`tools/assets/bookk-B5.docx`를 base로 열어 판형·여백·제본 여백·테마를 상속했다. 본문 10.5pt 부크크 명조 Light, 제목 부크크 고딕 Light, 명령 10pt Consolas, 검정 문자·단순 표를 유지했다. 표제에는 Word Title 스타일을 적용했다. URL은 주소 문자를 생략하거나 하이픈을 추가하지 않고 줄을 나눴다.

번들 `render_docx.py`는 설치 환경에서 soffice.exe를 찾지 못했다. Microsoft Word의 비공개 PDF 출력과 pypdfium2로 페이지 PNG를 만들어 확인했다. 임시 PDF·PNG는 build에만 보관하며 배포하지 않는다. 11장의 30쪽과 부록 27쪽을 모두 육안 검토했다. 후속 수정에서는 기존에 검토한 페이지와 픽셀 동일성을 대조하고 변경 지면을 다시 확인했다. 최종 11장은 이전 30쪽 렌더와 21·27쪽이 달라 해당 두 쪽을 재확인했다.

실제 그림 바이트와 삽입 순서, 본문·표·명령·캡션, 전체 참고 URL, 관계 링크, 지정 글꼴, 템플릿 치수·테마, 증거 원본·사본 해시, DQL 재사용, 451개 색인, 31개 실습 대응을 정적으로 검사했다. 결과와 최종 DOCX 해시는 `chapter11-appendices-validation.json`, 그림 출처는 `chapter11-assets.json`에 있다. 정적 검사 자체는 실습 입력을 실행하지 않는다.

1~10장 DOCX·JSON, REV01, 강의·kt66 저장소는 수정하지 않았다. 기존 미추적 `editorial/evidence/chapter07/2026-11-02/`도 이번 커밋에서 제외했다. 1장의 VMware·Ubuntu 설치 화면 두 곳은 기존 저자 촬영 지시 상태로 유지한다. 각 장은 후속 교정 대상 초안이며 출판 최종본으로 표시하지 않는다.
