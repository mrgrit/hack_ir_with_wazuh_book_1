# 시범 원고 검토 기록

## 목적과 범위

학습자가 직접 조작하는 설명 밀도와 B5 지면의 가독성을 확인하는 3개 실습 시범본이다.
설치된 kt66을 전제로 한다. 기본 운용 장 전체를 먼저 완성한 것은 아니다.
29쪽 전체를 31개 실습으로 단순 곱해 최종 분량으로 확정하지 않는다.

## 원본과 신규 절차의 차이

| 항목 | 기존 강의 | 이번 시범본 | 재촬영 필요 |
|---|---|---|---|
| SQLi | curl·sqlmap 결과 혼합 | 정상 요청 후 curl 공격 요청 1건 | 해당 1건 요청·검색·원문 |
| SSH | Hydra 명령, kt66-host 대상 캡처 | Bastion에서 수동 실패 2회 후 성공 | Bastion 실패·성공 타임라인 전체 |
| osquery | 잘린 공개키·백그라운드 nc 예시 | 실제 임시 공개키, 전경 nc, 개별 원복 | 키 주석·포트·삭제 확인 |

과거 결과의 건수를 새 절차의 기대 건수로 쓰지 않았다. 실제 경보와 상태 조회를 구분했다.
SQLi의 200을 침해 성공으로, 실패 뒤 로그인을 계정 탈취로, added를 악성 변경으로 단정하지 않는다.

## 확인한 것

- PPTX의 표시 순서로 페이지 번호를 확인하고 원본 PNG를 추출했다.
- 화면 출처를 assets/screens/provenance.json에 기록했다. 실제 결과를 생성형 그림으로 만들지 않았다.
- SSH 캡처가 kt66-host 대상임을 확인하고 원고의 Bastion 절차와 차이를 표시했다.
- osquery 로컬 설정의 쿼리 이름, 60초 간격, 로컬 전용 리스닝 주소 제외 조건을 대조했다.
- 기존 공개키를 덮지 않고 실습 표지의 행만 제거하는 절차를 작성했다.
- Cairo/Pango로 B5 PDF 24쪽을 출력했다. 배치 기록은 print-layout.json이다.
- PDF 1·8·14·18쪽을 이미지로 변환해 직접 확인했다. 확대 캡처와 본문 글자 크기를 검토했다.
- SSH 화면에서 확대 시 계정 열이 잘리는 것을 발견해, 계정과 출발지가 함께 보이는 원본 상세 화면으로 교체했다.
- 최초 제작 때 Chromium은 실행 권한 제한, LibreOffice는 실행 실패로 사용하지 못했다. 이번 개정에서는 변경된 실행 권한으로 Chromium을 실행하여 HTML 29쪽의 넘침·이미지 로딩을 확인했다. 결과는 layout-check.json이다.

## 아직 확인하지 않은 것

- 새 절차를 초기 상태 kt66에서 학습자 관점으로 전체 재실행.
- 해당 환경의 실제 메뉴, 필드 존재, 경보 발생, 원복 결과에 대한 신규 캡처.
- 편집 PDF의 실제 크기 종이 출력. 디지털 이미지 판독은 인쇄 검수의 대체가 아니다.
- 초보 학습자의 무도움 완주 여부.

이 항목이 끝나기 전에는 “검증 완료 교재”로 표기하지 않는다.

## 재실행·촬영 순서

1. 강사가 배부할 호스트·웹·Bastion 주소와 계정, 센서 상태를 확인한다.
2. 각 실습은 원고 순서대로 한 단계씩 수행하고 입력·원문·검색 화면을 남긴다.
3. 실패·성공을 모두 직접 읽고 설명과 일치하는지 확인한다.
4. 학생 화면에 필요한 필드만 표시하고, 글꼴을 크게 한 뒤 캡처한다.
5. 키·개인정보를 확인하고 마스킹한다. 필드·값을 합성해 성공 화면을 만들지 않는다.
6. B5 PDF를 100%로 인쇄해 코드·필드명·값·기호를 읽고 재촬영 여부를 결정한다.

## 시각 기준

크림 배경, 남색 윤곽, 청록 정상 흐름, 주황 조사·설명, 적색 공격, 청색 관리·분석을 사용한다.
픽셀오피스 그림은 내장 imagegen으로 생성한 개념용 PNG 삽화와 별도 조판한 SVG 설명으로 구성한다. 실제 화면이 아님을 본문에 표시한다. 한글은 일반 글꼴로 조판한다.
기존 캡처 중 확대 영역 밖의 긴 값은 잘릴 수 있으므로 본문에서 해당 필드를 직접 펼쳐 읽도록 안내하고,
배포본 촬영에서는 필수 값 전체가 읽히도록 캡처를 분할한다.

## sed 설명 보완

- 기존 22쪽의 원복 절차를 두 쪽으로 나눴다. 현재 확장본에서는 26~27쪽이다. sed의 용도·기본 구문, -i, 작은따옴표, /패턴/, 공백, $, d, 대상 경로를 설명한다.

- 명령의 첫 등장에 구문·옵션·확인 방법을 설명하는 원칙을 AGENTS.md에 추가했다.

## 2026-11-01: 개념·선행 조건·삽화 개정

- 시범본은 B5 29쪽이다. 본문·코드 글자 크기를 유지하고 설명 단위로 페이지를 나눴다.
- 2쪽: kt66 준비 담당자가 설치를 마친 상태에서 독자가 시작한다는 전제를 설명했다.
- 16~21쪽: osquery의 사전 설치, 가상 테이블·행·열·SQL, 서비스 확인, osqueryi 직접 조회, osqueryd 예약 조회, Wazuh 수집, 관찰 간격의 한계를 설명했다.
- `processes` 등 이번 실습의 테이블이 조회 시 정보를 구성한다는 점과, 차이 비교를 위해 이전 결과를 저장하는 동작을 구분했다. 모든 osquery 테이블이 같은 방식이라는 주장은 하지 않는다.
- SQL·종료 명령 등 복사용 예제 네 개를 추가했다. 새 직접 조회 절차의 kt66 실행 및 화면 촬영은 아직 하지 않았다.
- 임시 텍스트 파일에서 sed 패턴에 맞는 행만 삭제되고 다른 키 주석 행은 보존되는 것을 확인했다. 실제 authorized_keys에는 접근하지 않았다.
- overview·sqli·ssh·osquery 삽화 네 장을 교체했다. 원본 PNG, 내장 imagegen 도구의 최종 프롬프트, 한글 조판 SVG를 저장했다. 출처와 프롬프트는 illustration-prompts.json에 있다.
- PDF 1·5·11·16~21·26쪽을 이미지로 변환해 삽화·한글·코드·페이지 하단을 직접 확인했다. HTML 29쪽에는 내용 넘침이나 이미지 로딩 실패가 없다. 실제 종이 출력은 별도 확인이 필요하다.
- Python 구문, 원고 예제 경로, git diff 공백 검사를 통과했다. 전체 실습 성공을 검증한 것은 아니다.
