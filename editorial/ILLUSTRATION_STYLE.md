# 삽화 화풍과 구도

## 기준

[사용자가 지정한 픽셀 그림 모음](https://m.blog.naver.com/studygir/220961448822)의 구형 PC·실내 그림을 보고 화풍을 정했다. 원본 그림을 책에 재사용하지 않고, 내장 imagegen으로 새 장면을 생성했다. 최종 프롬프트는 illustration-prompts.json, 출력 PNG는 assets/illustrations/에 저장한다.

- 옛 PC 어드벤처 게임의 선명한 픽셀, 제한된 색면, 점무늬 음영을 사용한다.
- 남색 윤곽과 보라·분홍·청록·파랑, 베이지색 구형 장비를 공통으로 사용한다.
- 공격자는 어두운 후드 차림이며 뒷머리와 등이 보인다. 얼굴을 억지로 노출하지 않는다.
- 방어자는 헤드셋·이어피스·마이크 없이 얼굴이 보이는 앞쪽 3/4 방향이다. 모니터 화면은 방어자를 향하고, 독자에게는 모니터 뒷면이 보인다.
- 책상·키보드·손·모니터를 실제 사용할 수 있는 위치에 둔다. 설명을 위해 물체를 투시하거나 화면을 양면으로 만들지 않는다.
- 하나의 장면에서 시점과 원근을 일관되게 유지한다. 거대한 돋보기, 떠 있는 종이·창 등으로 화면 내용을 보여주지 않는다.
- 실제 화면·명령·필드명은 스크린샷과 본문에서 보여준다. 삽화의 한글 제목과 흐름 설명은 SVG로 별도 조판한다.

## 장면별 장비

| 장면 | 주요 장비와 표현 |
|---|---|
| 전체 흐름 | 구형 데스크톱, 낮은 랙과 네트워크 장비, 분석용 CRT |
| SQL 인젝션 | 수평형 PC, 독립된 보안장비와 웹 서버 타워 |
| SSH 인증 | 구형 휴대용 컴퓨터, 타워 서버, 별도 단말기와 스위치 |
| osquery | 워크스테이션, 높이가 다른 랙 서버와 타워, 비교 기록을 읽는 방어자 |

이 장면들은 역할을 설명하는 개념 삽화다. 공격자와 방어자가 같은 방에 있는 표현이나 장비의 공간 배치를 실제 kt66 네트워크 구성으로 해석하지 않는다. osquery·Wazuh는 그림의 장비 위에서 동작하는 소프트웨어다.

## 확인

네 PNG의 인물 방향·모니터 면·장비 배치를 확인했다. PDF 1·5·11·20쪽에서 그림의 잘림과 설명 글자 배치를 확인했다. HTML 전체 29쪽에서 내용 넘침과 이미지 로딩 실패가 없음을 확인했다. 종이 출력의 색감과 점무늬 재현은 별도 인쇄 검수 대상이다.

## 반복을 피하는 장면 설계

화풍과 등장인물의 역할은 통일하되, 장소·시간대·조명·행동을 매번 설계한다. 참고 글의 여러 실내·야간·주간 그림에서 장면 구성의 폭을 참고한다. 하나의 방에서 장비만 교체하는 방식을 기본 템플릿으로 사용하지 않는다.

| 현재 시범 장면 | 공격자의 행동 | 방어자의 행동 | 공간·빛 |
|---|---|---|---|
| 전체 흐름 | 앉아서 명령 입력 | 앞으로 기울여 화면 확인 | 창이 큰 낮의 실습실 |
| SQL 인젝션 | 마우스를 쓰며 응답 확인 | 종이 기록의 의심 항목 짚기 | 유리 너머 서버실, 저녁 조명 |
| SSH 인증 | 머리에 손을 올리고 재시도 고민 | 시각과 순서를 노트에 기록 | 블라인드와 작업등이 있는 야간 사무실 |
| osquery | 자리에서 일어나 호스트 조작 | 두 자료의 결과 비교 | 밝은 아침의 장비실 |

인물의 감정은 장면을 읽기 쉽게 하는 연출이다. 로그인 성공·실패나 침해 여부는 본문의 실제 기록으로 판단한다. 삽화의 낮·밤이 실습 로그의 실제 시간대를 뜻하지 않는다. 헤드셋은 통화 등 설명상 필요한 장면에만 사용한다.
