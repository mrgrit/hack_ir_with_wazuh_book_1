## 기술 교정 근거

- `df`의 Size와 Avail을 각각 파일시스템 전체 크기와 남은 공간으로 구분했다. 가상 디스크 할당량과 루트 파일시스템 배정도 분리해 확인한다.
- C01-18의 실제 입력은 Docker·Compose 버전 및 `docker ps`이다. 본문의 확인 설명을 해당 입력과 맞췄다.
- `vm.max_map_count` 262144 이상을 실행 준비와 완료 기준에 포함했다.
- 기준 코드의 install에서 WEB_HOST_IP를 저장하면 up이 재사용한다. 값이 없을 때에는 up도 감지·확인 후 저장한다.
- 호스트 센서 설치의 경고와 이후 서비스 상태 확인을 연결했다. up 완료 문구 뒤에도 네 서비스와 Wazuh 연결을 각각 확인한다.
- 2장에 필요한 bastion을 상시 실행 서비스 확인 목록에 추가했다. 초기 작업용 netglue·agent-observer-setup의 Exited (0)은 지속 실행 서비스의 종료와 구분한다.
- 기준 `kt66.sh`의 `cmd_down()`은 선택 인자가 없을 때에도 `down "${1:-}"`로 빈 인자를 전달한다. REV03 C01-23은 `~/kt66`에서 `docker compose down`을 직접 사용하도록 했다. 전후 `ps -a`와 오류 확인을 포함한다. 코드 정적 대조에 따른 선택이며 실제 Docker 오류 재현으로 기록하지 않는다.
- Compose의 `down`에서 `-v`를 생략하면 이름 있는 데이터 볼륨을 유지한다. 컨테이너 내부에만 만든 파일과 VM 스냅샷 복원 이후의 Wazuh 기록은 별도로 설명했다.
- Ubuntu의 컴퓨터 이름 kt66-book, 등록된 에이전트 이름 kt66-host, systemctl의 active와 Wazuh의 active를 구분했다.

## 그림·문체·조판

관계 도식 8개를 REV03 전용 자산으로 작성했다. 실제 UI 4개와 현재 인물 삽화 4개를 재사용했다. 인물 원본은 각각 열어 몸·손·의자·책상·작업 대상의 방향을 확인했다. 삽화의 장면은 실습팀 소개 → 실습망 연결 → 설치 상태 확인 → 수집기 조회이며, 캡션은 그 장면의 행동과 다음 확인 대상을 명시한다.

현재 삽화는 별도 진행 중인 수정본이므로 REV03에서 사용하는 네 파일만 바이트 그대로 전용 디렉터리에 보관했다. 다른 삽화·REV02 조판기·기존 원고의 진행 중 변경은 이번 커밋에 포함하지 않는다. 원본과 사본의 대응은 `chapter01-illustration-sources.json`에 기록했다.

의문형·문학적 제목, 불특정 주의문, 제작 메모를 사용하지 않았다. 설명은 대상·명령·출력값·다음 확인 행동으로 작성했다. 계정·주소·도메인·실행 위치·원상복구 표기를 통일했다. 표 15개의 머리행은 회색 음영과 가로·세로 가운데 정렬, 굵은 글씨를 적용했다. 본문의 명령 6개는 연한 회색 바탕·안쪽 여백·왼쪽 구분선으로 구별했다. 실제 UI 캡처 4개에는 0.5pt 회색 테두리를 넣었다.

최종 38쪽을 확인했다. 최초 전체 지면을 순서대로 읽고 수정했으며, 최종 수정 때는 이전 검수 PNG와 해시가 같은 쪽을 제외한 변경 지면을 다시 열었다. 마지막 자산 경로 분리 뒤의 38쪽은 직전 검수 렌더와 모두 동일했다. 머리말 그림의 단독 쪽, 표의 한 행만 남는 쪽 나눔, 보충 상자의 테두리, 긴 참고 URL의 줄 나눔을 수정·확인했다.

추가 서식 요청은 두 차례 렌더해 확인했다. 명령 상자 변경으로 달라진 6쪽을 먼저 읽고, 캡처 테두리와 표 머리행 굵기를 적용한 뒤 달라진 21쪽을 순서대로 다시 읽었다. 나머지 지면은 직전 검수 PNG와 해시가 같았다. 최종 분량은 38쪽이다.

## 검증 결과와 범위

- JSON 본문·표·캡션·입력이 DOCX에 모두 포함됨을 대조했다.
- C01-01~28 복사용 입력이 수록 원고와 일치한다. Bash `-n` 구문 검사 28개를 통과했다. 명령 실행 시험은 아니다.
- DOCX 내장 그림 16개의 해시가 실제 자산과 일치한다.
- 판형 188×263mm, 제본 여백을 제외한 본문 영역 127×192mm를 템플릿에서 상속했다.
- 전체 참고 URL 4개를 DOCX 및 Word 렌더의 문자열과 대조했다. PDFium의 줄 끝 하이픈 추출 문제는 pypdf로 재확인했으며 인쇄된 주소와 일치했다.
- 측면 판면 초과 0쪽. 자동 검사 결과와 산출물 해시는 `chapter01-validation.json`, 시각 검토 이력은 `chapter01-visual-review.json`에 기록했다.
- REV02 1장·부록 A·템플릿·원본 그림 등 작업 전 기준 20개 파일의 해시가 유지됐다.

새 VM 설치·공격 실행·신규 UI 촬영은 수행하지 않았다. 기존 캡처의 연결 현황과 새로 작성한 독자 절차를 구분한다. LibreOffice가 없어 문서 스킬의 기본 렌더 도구는 실행되지 않았으며, 설치된 Word의 읽기 전용 렌더와 PDFium 이미지로 검수했다. PDF는 임시 검수물로만 사용한다.

## 후속 장에서 유지할 내용

2장 교정 시 1장의 준비 기록과 사례 번호를 이어 사용한다. 3장에서는 같은 로그인 실패 기록을 검색한다. 부록 A의 상세 설치는 이번 교정 범위에서 보존했으며, 차후 부록 교정 시 REV03 본문의 최신 용어·기록 양식 참조와 맞춘다. 새 PC·VM에서 설치부터 재기동까지 따라 하는 실독 시험은 별도 실행 검증으로 남아 있다.
