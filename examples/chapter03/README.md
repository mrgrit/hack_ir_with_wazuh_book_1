# 3장 실습 예제

DOCX의 순서대로 한 파일씩 사용합니다. 전체 폴더를 실행하는 스크립트는 없습니다.
SSH 접속은 본인의 kt66 실습 서버에서 한 번만 수행합니다. 계정을 새로 만들지 않습니다.

| 파일 | 실행 위치·용도 | 검증 상태 |
| --- | --- | --- |
| `00a`, `00b` | Ubuntu 호스트에 SSH 클라이언트가 없을 때만, 한 명령씩 설치 | 이번 환경에는 이미 있어 설치 실행 생략 |
| `01`, `02` | 호스트에서 SSH 버전·현재 시각 확인 | 호스트 조회 |
| `03-ssh-probe.txt` | 호스트에서 bastion의 공개 포트로 SSH 실패 1회 생성 | 실제 비밀번호 실패 확인 |
| `04-marker.dql` | Discover의 DQL 검색창 | 실제 3건: bastion 2 + 호스트 감사 1 |
| `05-bastion-marker.dql` | 같은 검색창에서 bastion으로 제한 | 실제 2건 |
| `06-user-field.dql` | 추출된 사용자 필드로 검색 | 실제 2건 |
| `07-search.http` | Indexer management → Dev Tools의 왼쪽 편집기에 전체 복사 | UI 실행, 200 OK·2건 |
| `07-search-body.json` | 위 요청의 JSON 본문만 보관. 단독 콘솔 요청이 아님 | JSON 구문 및 HTTP 파일과 일치 확인 |
| `observed-search-response.json` | 실제 응답을 읽는 참고 자료. 실행·가져오기 대상 아님 | 실측 응답 |
| `08`~`13` | 호스트의 kt66 저장소에서 실행하는 개별 점검 명령 | 소스 대조. 현재 집필 계정 Docker 권한 부족으로 실행 검증 보류 |
| `localfile-reading-only.xml` | kt66의 기존 로그 수집 블록을 읽는 참고 자료 | 설정에 다시 추가하지 않음 |
| `worksheet.txt` | 자신의 조사 결과 기록 | 빈 양식 |

호스트 예시 주소 `192.168.0.189`와 SSH 포트 `2204`는 자신의 환경에 맞춥니다.
조회 시간은 최근 1시간입니다. 오래된 기록을 찾을 때는 Discover 시간과 JSON의 `range`를 각각 바꿉니다.
실측 자료의 날짜·ID·출발지·문서 수를 본인 실습의 고정 정답으로 사용하지 않습니다.

검증 시 SSH 옵션 `UserKnownHostsFile=/tmp/book-ch03-qa/known_hosts`를 추가하여 저자용 임시 호스트 키 파일을 사용했습니다.
독자용 명령은 일반적인 `~/.ssh/known_hosts`를 사용합니다. 인증·접속 대상·실패 생성 방식은 같습니다.
최초 서버 지문은 주소·포트와 함께 확인하고 수락합니다. 실제 SSH 서버가 기록한 로그를 수집했으며 합성 로그를 주입하지 않았습니다.

이 실습은 계정·규칙·서비스 설정을 변경하지 않습니다. 분석용 경보를 삭제하지 않고 남깁니다.
