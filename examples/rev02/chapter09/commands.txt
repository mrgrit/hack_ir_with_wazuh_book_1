[C09-07] kt66-bastion · root 관리 셸

sudo -l은 현재 사용자의 허용 명령을 표시한다. ls -l은 파일 소유자·권한·크기를 읽는다.

[C09-09] kt66-bastion · SSH로 접속한 ccc 셸
printf는 형식에 맞춰 출력한다. %s는 문자열, \n은 줄바꿈이다. 작은따옴표는 괄호 등의 셸 해석을 막는다. 파이프(|)는 출력을 tee에 전달한다. tee는 입력을 화면과 파일에 함께 쓰며 기존 파일은 덮어쓴다. sudo는 tee의 쓰기에 적용된다. chmod 0440은 소유자·그룹 읽기만 허용한다. visudo -cf는 지정 파일을 검사한다.

printf '%s\n' 'ccc ALL=(ALL) NOPASSWD:ALL' | \
sudo tee /etc/sudoers.d/99-book09-lab
sudo chmod 0440 /etc/sudoers.d/99-book09-lab
sudo visudo -cf /etc/sudoers.d/99-book09-lab
sudo visudo -c
확인: 실습 파일과 전체 sudoers 검사에 parsed OK가 나와야 한다. 실패하면 관리 셸을 유지한 채 실습 파일을 제거하고 전체 정책을 다시 검사한다.

[C09-14] 공격자 VM · att 셸
ssh-keygen은 SSH 키 쌍을 생성·관리한다. -t는 알고리즘, -N 뒤 빈 작은따옴표는 이 임시 키의 빈 암호문, -C는 식별용 주석, -f는 파일 경로이다. -l은 지문 표시이다. .pub가 공개 키이고 확장자 없는 파일이 개인 키이다.

ssh-keygen -t ed25519 -N '' \
-C book09@attacker -f ~/book09/book09_key
ssh-keygen -lf ~/book09/book09_key.pub
cat ~/book09/book09_key.pub
확인: 새 키 지문과 공개 키 한 줄을 기록한다. 개인 키는 공격자 VM에만 둔다. 공개 키 끝 주석은 작성자가 정한 이름이다. 키 소유자는 등록 내역과 지문으로 확인한다.

[C09-15] kt66-bastion · root 관리 셸
기존 SSH 키 파일의 권한과 백업 대상의 상태를 기록한다.
stat은 파일 속성을 출력한다. -c는 형식, %a는 숫자 권한, %U·%G는 소유자·그룹, %n은 경로이다. 큰따옴표는 형식 전체를 하나의 인자로 묶는다.
ls -ld /home/ccc/.ssh
ls -l /home/ccc/.ssh/authorized_keys
ls -l /root/book09-authorized_keys.before
stat -c "%a %U %G %n" \
/home/ccc/.ssh /home/ccc/.ssh/authorized_keys
확인: 제시한 사례에서는 기존 디렉터리 755, 파일 600, 소유자 ccc이다. 백업 이름은 없어야 한다.

[C09-16] kt66-bastion · root 관리 셸
cp는 복사하며 -p는 권한·소유자·시각을 보존한다. sha256sum은 파일 내용의 SHA-256 값을 계산한다.

/root/book09-authorized_keys.before
확인: 기존 키 파일과 백업 해시가 같아야 한다. 이 백업으로 실습 전 키 목록을 복원한다.

[C09-17] kt66-bastion · root 관리 셸
두 경로가 모두 없을 때의 준비이다. install은 복사와 속성 설정을 하는 도구이다. -d는 디렉터리 생성, -m은 권한, -o·-g는 소유자·그룹이다. /dev/null은 읽을 내용이 없는 특수 파일로 빈 파일을 만든다. .ssh만 이미 있다면 첫 명령은 생략하고 기존 속성을 유지한다.

install -m 600 -o ccc -g ccc /dev/null \
/home/ccc/.ssh/authorized_keys
ls -ld /home/ccc/.ssh
ls -l /home/ccc/.ssh/authorized_keys
확인: 새 파일은 ccc 소유 0600이다. 이 조건부 경로에서는 백업 복원이 아니라 추가한 파일 제거로 원상복구한다. 기존 authorized_keys에는 install을 실행하지 않는다.

[C09-20] 공격자 VM · att 셸
-i는 개인 키 파일이다. -o는 SSH 옵션, IdentitiesOnly는 지정한 인증 키 사용, BatchMode는 암호 입력 같은 대화형 질문 억제, PreferredAuthentications는 공개 키 인증 지정이다. 원격 작은따옴표 안 세미콜론(;)은 두 명령을 순서대로 실행한다.

ssh -p 2204 -i ~/book09/book09_key \
-o IdentitiesOnly=yes -o BatchMode=yes \
-o PreferredAuthentications=publickey \
ccc@192.168.0.107 'hostname; id'
확인: 암호 입력 없이 bastion, uid=1000(ccc)가 나온다. 암호 방식의 자동 대체로 성공한 것을 공개 키 성공으로 오인하지 않도록 옵션을 함께 쓴다.

/home/ccc/.ssh/authorized_keys

/home/ccc/.ssh/authorized_keys

[C09-27] 공격자 VM · att 셸
cat에 here-document로 여러 줄을 입력한다. <<'EOF'부터 EOF 앞까지가 입력이고, 구분자를 따옴표로 묶어 작성 중 $()를 실행하지 않는다. >는 파일 생성·덮어쓰기이다. 파일 안의 #!/bin/sh는 셸 지정, $()는 실행 시 명령 출력 대입이다. id -un은 유효 사용자 이름, >>는 결과 누적이다.

printf "book09-cron user=%s host=%s\n" \
"$(id -un)" "$(hostname)" >> /tmp/book09-cron-result
EOF
cat ~/book09/www/x.sh
확인: 실행 대상 스크립트가 이름 두 개를 기록하는 내용인지 읽는다. EOF는 줄 처음에 단독으로 입력한다.

[C09-28] 공격자 VM · att 셸
ss는 소켓 상태를 표시한다. -l은 대기, -t는 TCP, -n은 숫자 주소이다. 따옴표 안 sport 조건은 로컬 포트를 고른다. 기존 8000 서비스가 없을 때 실행한다. python3 -m은 모듈 실행, --bind는 수신 주소, --directory는 공개할 디렉터리이다.

python3 -m http.server 8000 \
--bind 192.168.0.108 --directory /home/att/book09/www
확인: Serving HTTP 안내가 나오면 이 창을 유지한다. 요청이 오면 경로와 응답 코드가 표시된다. 9.6까지 사용한 뒤 Ctrl+C로 종료한다. [9-5]
