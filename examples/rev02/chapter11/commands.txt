REV02 복사용 입력 — 본문의 선행 조건과 원상복구 절차를 확인하고 한 블록씩 사용한다.

[Q11-01] Windows · Discover · wazuh-alerts-*
사례 A에서 같은 출발지의 인증 실패 5760과 성공 5715를 함께 찾는다.
AND는 모든 조건, 괄호 안 OR는 두 규칙 중 하나의 조건이다.
agent.name: "bastion" AND
data.srcip: "192.168.0.108" AND
(rule.id: "5760" OR rule.id: "5715")
확인: 8장의 고정 기간에는 22건이다. 수는 실습 당시 검색 결과이며 자신의 재실행 횟수와 같을 필요가 없다.

[Q11-02] Windows · Discover · wazuh-alerts-*
사례 B의 기간으로 바꾼 뒤 bastion의 키 파일 FIM 기록을 찾는다.
syscheck는 파일 무결성 감시의 필드 묶음이다.
agent.name: "bastion" AND rule.groups: "syscheck" AND syscheck.path: "/home/ccc/.ssh/authorized_keys"
확인: 추가 때와 원상복구 때의 modified 두 건을 구분한다. 같은 경로가 나오는 kt66-host 기록과 합치지 않는다.

[Q11-03] Windows · Discover · wazuh-alerts-*
공개 키 인증 성공만 원문 문구까지 지정해 찾는다.
srcip는 접속한 컴퓨터의 주소이며 키 소유자의 신원을 자동으로 증명하지 않는다.
agent.name: "bastion" AND rule.id: "5715" AND data.dstuser: "ccc" AND data.srcip: "192.168.0.108" AND full_log: "Accepted publickey"
확인: 07:50:27.428 KST의 경보 원문에서 07:50:25의 Accepted publickey와 키 지문을 읽는다.

[Q11-04] Windows · Discover · wazuh-alerts-*
사례 C의 시간 범위에서 현재 또는 이전 출력에 31337이 포함된 533 경보를 찾는다.
별표는 주변 문자가 있어도 해당 문자열을 포함하는 조건이다.
agent.name:"kt66-host" AND rule.id:533
AND (full_log:*31337* OR previous_output:*31337*)
확인: 현재 출력과 previous_output의 nc 행을 대조한다. 포트 번호가 다른 열에 우연히 나타난 경우는 제외한다.

[Q11-05] Windows · Discover · wazuh-alerts-*
반복 DROP 경보를 해당 출발지로 좁힌다.

agent.name:"kt66-host" AND rule.id:4151
AND data.srcip:"192.168.0.108"
확인: full_log의 한 목적지 포트와 previous_output의 일부 행이 스캔 전체 목록은 아니다.

[Q11-06] Windows · Discover · wazuh-archives-*
검색 패턴을 wazuh-archives-*로 바꿔 개별 수집 기록을 찾는다.
alerts의 규칙 조건과 기존 필터 칩을 제거한다.
agent.name:"kt66-host"
AND location:"/var/log/kern.log"
AND data.action:DROP
AND data.srcip:"192.168.0.108"
확인: 사례 조회 기간의 결과 592건은 수집된 문서 수이다. 전송 패킷 수나 고유 목적지 포트 수로 읽지 않는다.

[C11-01] Windows · PowerShell · 저장소 루트
새 분석 디렉터리의 이름이 비어 있고 원본 사례 파일이 준비됐는지 확인한다.
Test-Path는 경로의 존재 여부를 True 또는 False로 출력한다. Get-ChildItem은 디렉터리 안의 파일을 나열한다. .\는 현재 위치이다.
Get-Location
Test-Path .\book11-analysis
Get-ChildItem .\examples\rev02\chapter11\evidence
확인: 분석 디렉터리가 아직 없고 case-a.json·case-b.json·case-c.json·manifest.json이 있는지 확인한다.

[C11-02] Windows · PowerShell · 저장소 루트
New-Item은 디렉터리를 만든다. Copy-Item은 JSON 파일을 복사한다. *.json은 확장자가 json인 파일, 줄 끝 백틱(`)은 PowerShell의 줄 연결이다. 뒤에 공백을 붙이지 않는다.

New-Item -ItemType Directory .\book11-analysis
Copy-Item .\examples\rev02\chapter11\evidence\*.json `
  .\book11-analysis\
Get-ChildItem .\book11-analysis
확인: 분석 사본의 네 파일을 확인한다. 원본 예제는 편집하지 않고 사본에 분석 결과를 별도 파일로 추가한다.

[C11-03] Windows · PowerShell · 저장소 루트
Get-FileHash는 파일 내용의 해시를 계산한다. -Algorithm SHA256은 알고리즘 지정이다. Get-Content는 매니페스트 내용을 읽는다.

Get-FileHash .\book11-analysis\case-a.json `
  -Algorithm SHA256
Get-Content .\book11-analysis\manifest.json
확인: case-a.json 해시를 manifest의 해당 sha256과 대조한다. 나머지 case-b·case-c도 파일명을 바꿔 확인한다.

[C11-04] Windows · PowerShell · 저장소 루트
Get-Content -Raw는 전체 파일을 문자열로 읽고 ConvertFrom-Json은 JSON을 PowerShell 객체로 바꾼다. 파이프(|)는 앞의 결과를 다음 명령으로 전달한다. $caseA는 이 세션의 변수이다. Select-Object -First 1은 첫 기록 하나, Format-List *는 그 기록의 속성을 목록으로 표시한다.

$caseA = Get-Content -Raw `
  .\book11-analysis\case-a.json | ConvertFrom-Json
$caseA | Select-Object -First 1 | Format-List *
확인: 첫 기록의 evidence_id·timestamp·agent·rule·data·full_log를 확인한다. 중첩된 객체는 다음 명령으로 펼친다.

[C11-05] Windows · PowerShell · 저장소 루트
대괄호 안의 0([0])은 첫 요소, 마침표는 속성 접근이다. agent는 수집 대상, data는 원문에서 추출한 값, full_log는 수집한 원문이다.

$caseA[0].agent | Format-List *
$caseA[0].data | Format-List *
$caseA[0].full_log
확인: 원문에서 계정·IP·포트를 찾아 추출 필드와 대조한다. 원문에 없는 값을 분석자가 보충했다면 관찰값과 구분해 적는다.
